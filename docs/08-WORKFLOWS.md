# Common Workflows

## Create or simplify a compact harness

```text
inspect instructions, repository state, commands, and documents
  -> establish the six coordinated harness artifacts
  -> make init.sh executable
  -> run relevant verification
  -> record evidence and next action
```

Use `harness-slim`. Preserve canonical project documents and create no broad
documentation tree merely because the harness exists.

## Audit before changing a harness

```text
inspect root and scoped instructions
  -> inventory harness artifacts and verification evidence
  -> assess applicable rubric criteria
  -> report verdict, findings, strengths, and priority fixes
```

Use `harness-slim-review`. Inspect `init.sh` before running it, and do not run
formatting or lint fixes without authorization.

## Clean recurring drift

```text
orient on instructions and canonical patterns
  -> classify candidates
  -> select one confirmed cleanup batch
  -> make the smallest repair
  -> run targeted and repository verification
  -> record a guardrail only when recurrence justifies it
```

Use `harness-slim-gardenring`. Keep feature work and garden work separate.

## Design documentation architecture

```text
inspect topology, documentation, workflow pressure, and failures
  -> select a scale profile
  -> assign canonical owners and reading routes
  -> propose only justified artifacts
  -> hand accepted documents to the writer
```

Use `agent-docs-architect`. The default result is a blueprint, not modified
repository documentation.

## Write one document

```text
inspect evidence and existing routes
  -> confirm the document's one responsibility
  -> use the matching writer reference
  -> draft the smallest useful structure
  -> link canonical sources and run the quality gate
```

Use `agent-docs-writer` when the document type and ownership are already known.
